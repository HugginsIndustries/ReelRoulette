Field validation pattern

Every field below is live. Point at a red icon, or put the cursor in a flagged field, to see its tooltip; on a touch screen tap the icon. Magenta dashed boxes are mockup notes, not part of the WebUI.

Duration (Filter tab, General)

Empty means no duration, so an empty field is never flagged. Anything other than whole MM:SS or HH:MM:SS (minutes and seconds under 60) or a number of seconds is flagged as it is typed: “1:7x”, “12abc”, and “1:75” all are. Today the WebUI reads “1:7x” as 1:07 and “12abc” as 12 seconds.

New preset name (Filter tab, Presets)

Required: an empty name is flagged only once the user has typed in it, but Add Preset can't proceed meanwhile. A name a saved preset already has, ignoring case, is flagged as it is typed. Saved presets here: Favorites, Short clips, Long videos.

Edit Tag dialog: tag name

The name opens filled in. Emptying it flags it, and Save can't proceed until it has a name. Delete moves here from the chip, and asks first.

Edit Category dialog: category name

New: the category's edit button opens this in place of today's rename prompt, and Delete moves here from the category row, asking first. The name is flagged when emptied, or when another category has it, ignoring case. Categories here: People, Places, Events; editing People.

Apply while the field that is not valid is out of view

The minimum duration below is not valid and sits at the bottom of General, out of view. The General tab carries the red icon, so the problem can be found from Tags or Presets too.

Apply's label dims and the red icon shows on its right. Pressing it applies nothing: it switches to General, scrolls the field into view, puts the cursor in it, and shows its tooltip.
