Commit Message:

M11a: Leave a newer or damaged catalog untouched and run without a library

- A `library.db`, `library.db.previous`, or `library.db.incoming` saved by a newer version, or one that cannot be opened or read at the moment, is left byte-identical by open, replace recovery, and import, and the version is read from the file header so no sidecar files are created.
- A catalog that is not a database or is corrupt is still moved to `library.db.refused`, and an empty catalog is created only on a fresh install with no `library.db`, refused file, or catalog backup.
- Without a library the server keeps running: library routes return 503 with the reason and a `library_*` code, catalog backups and refresh don't run, and `last.log` gets a warning.
- `/control/status` adds `libraryState` and `libraryMessage`, and the Operator page shows the message.
- Backup rotation trims only valid current-version backups; other-version and unrecognized files stay and are not counted toward the limit or the gap.
- Desktop import refuses to replace a newer catalog, or one it cannot open to check, and changes nothing.
- Docs cover restoring a backup by hand; the Admin Refresh, Backup, and Duplicate Review milestone adds daily backup retention.
- `AGENTS.md` adds a best-effort rule: handle what can realistically happen in normal use, and leave improbable cases such as storage corruption out of code, tests, and reviews.
