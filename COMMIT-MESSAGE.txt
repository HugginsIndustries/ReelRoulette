Commit Message:

M11b: Make library browse cheap at any depth and reload the window in one request

- The catalog moves to schema version 3: opening a version 2 catalog migrates it in place in one transaction, adding a stored file name sort key that orders like OrdinalIgnoreCase and one index per sort mode and direction, and dropping the item tag index that duplicates its primary key and the file name fold index that no query uses; an interrupted migration leaves version 2 untouched and never writes a previous file.
- Insert and rename write the key with the row, and a new `nameSortKeys` refresh stage fills missing keys and recomputes them all after a key version change.
- Desktop import migrates a version 2 export; backup rotation still counts and trims only current-version backups, so version 2 backups stay.
- Browse counts are cached by catalog revision, search, and filter, so later pages, appends, and reloads at the same revision skip them.
- Library stats come from one pass grouped by source id and media type instead of matching paths and file extensions.
- The query limit rises to 10,000 and the WebUI reloads its loaded window in one request; each query writes one `last.log` line with its elapsed time.
- On a 49,053-item catalog, a page at offset 40,000 drops from 157-320 ms to 36-43 ms, a 5,000-tile reload from 2.7 s to about 0.1 s, and every sort order, filter, and stats figure is unchanged.
