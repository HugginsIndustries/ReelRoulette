# ReelRoulette Repository Context

This document is the high-level capability and ownership map for contributors and agents.
Keep it concise and current. Do not use it as a milestone changelog.

## Purpose and Architecture Direction

ReelRoulette is migrating from a monolithic desktop app to a thin-client, API-first system:

- Core/server owns domain logic and authoritative state.
- Desktop/WebUI are orchestration/render clients over API + SSE.
- Shared contracts (`shared/api/openapi.yaml`) drive cross-client behavior parity.

## Current Implemented Capabilities

- **Server host (`src/core/ReelRoulette.ServerApp`)**
  - Default single-process runtime serving API, SSE, media, WebUI assets, and Operator UI.
  - Control-plane surfaces under `/control/*` for runtime status/settings/pairing/lifecycle/testing/logs.
  - Localhost control requests are trusted, testing routes included. Every non-localhost control request needs the control token, through a `POST /control/pair` admin cookie or the token as a bearer header, never a query parameter, and there is no setting that turns this off. The server generates and saves a control token on start when none is set. Changing the token ends every control session and gives a non-localhost caller that changed it a fresh one, and a failed pairing attempt logs a warning with the remote address. A control session also authorizes API requests. On another machine the Operator shows only a control token prompt until a valid token is entered.
  - Operator testing mode supports deterministic fault simulation (version/capability mismatch, API unavailable, media missing, SSE disconnect).
  - mDNS LAN hostname advertisement for WebUI when enabled.
  - `REELROULETTE_DATA_DIR` moves the server's settings, catalog, backups, `last.log`, and thumbnails (`<folder>/thumbnails`) to one folder on every OS; unset, the server uses `ApplicationData/ReelRoulette` and `LocalApplicationData/ReelRoulette/thumbnails`. Server-starting verification scripts and the core test run set it to a temporary folder.
  - When the server starts stopping, it ends open event streams and cuts media responses still being sent, so stop, restart, and update apply do not wait for connected clients.
  - Host-UI abstraction keeps server runtime tray-agnostic:
    - Uses a cross-platform Avalonia tray host when available (lifecycle/refresh/operator shortcuts). The tray runs until the server shuts it down, always on the tray's UI thread. If the tray ends without that, `last.log` records it and the server keeps running.
    - The tray loads the Fluent theme, since on Windows Avalonia draws the tray menu as its own window. `last.log` records tray icon clicks, each time the Windows tray menu opens (with its size and item count) and closes, failed or rejected tray menu actions, tray UI errors, and Avalonia warnings and errors, each written once per run.
    - Falls back to a deterministic headless host when a tray cannot be created.
  - Startup-launch registration is host-managed with immediate toggle support through tray and Operator control settings:
    - Windows: user-scoped `HKCU` registration.
    - Linux: XDG autostart (`*.desktop` under `~/.config/autostart/` or `$XDG_CONFIG_HOME/autostart/`, with `Exec=`/`Path=` derived from the stable app path—**`APPIMAGE`** when running an AppImage, otherwise the process path—and host content root pinned to `AppContext.BaseDirectory` so session autostart finds config and WebUI assets).
  - Packaged server builds self-update via Velopack on an operator-controlled check → download → apply flow: a background loop checks the feed only (stable or dev via `devChannelEnabled` on `/control/settings`) to surface availability; download and apply are separate confirmed operator actions under `/control/update/*` and never run automatically; an immediate check still runs when the dev channel toggle changes.
  - On Linux, when running a Velopack **AppImage** (`APPIMAGE` set), the server reconciles a Freedesktop application menu entry (`reelroulette-server.desktop`) and hicolor icons under the user’s XDG data home on every launch—silent, with no first-run flag; `Exec=` always points at the current AppImage path.
  - The desktop client self-updates via Velopack with the same manual check → download → apply flow in Settings: stable or dev channel via `DevChannelEnabled` in `desktop-settings.json`, background check-only polling, and no restart without explicit Apply confirmation.

- **Domain execution (`src/core/ReelRoulette.Core` + server services)**
  - API-authoritative library operations (import, duplicates, auto-tag, playback stats, refresh pipeline).
  - The server opens a SQLite `library.db` at startup (WAL, synchronous=NORMAL, `user_version` 2). A missing database is created empty. A database at any other schema version, or one whose schema or revision row cannot be read, is moved aside to `library.db.refused` and refused. A healthy database is the live catalog: readers and writers update affected rows. `GET /api/library/catalog-checkpoint` returns a standalone copy of that database. Server catalog backups store the same kind of copy. A refused database stops startup. `POST /api/library/query` is the browse path: enabled sources, then filename or relative-path search, then filter, then sort, with `totalCount`, `searchBaselineCount`, and thumbnail layout fields on the returned page. Random selection uses that filter, plus the request's video and photo options, and does not keep a full-catalog cache. Playing one item reads that item and whether its source is enabled. `POST /api/library/item` reads one item by id or full path and does not add thumbnail fields. Library stats include the loudness baseline. Desktop connect and resync use library stats, sources, and the tag catalog, and read one item for now-playing when that file is not already loaded. An empty stored source display name is omitted. Tag-editor model reads, item-tag add and remove, category and tag upsert, rename, and delete, and auto-tag apply update catalog rows. Favorite, blacklist, record-playback, and clear-stats update those rows. A favorite clears blacklist, and a blacklist clears favorite. Clear-stats with no path list clears every played row. A path list clears only those items. Library stats are SQL aggregates for the same global and per-source figures. An item-state read returns only the requested paths, and an empty path list returns no items. Auto-tag scan and duplicate scan read catalog rows. A full-library auto-tag scan reads every item, a scan with no path list reads enabled sources, and an explicit list matches those full paths. Duplicate groups include only ready fingerprints. Duplicate apply deletes the non-kept files and rows. Source import inserts new files and updates existing paths. The disk walk does not hold the catalog lock. An existing path keeps its id, tags, favorite, blacklist, and playback stats. Files missing on disk stay until refresh. Refresh writes the columns each stage owns as that work finishes. A favorite, tag, blacklist, or playback change that commits during a stage stays. Thumbnail reuse trusts the revision stored on the item, which is that item's fingerprint, size, and write time, and does not walk those source files when that revision still matches. The stage writes that item's revision, width, and height as the item finishes. Browse reads those dimensions from the item row. `hasThumbnail` is still whether that item's JPEG exists. When the thumbnail stage completes, a JPEG whose item is not in the catalog is deleted, and the status line reports that cleanup. Opening the catalog does not delete those files. There is no thumbnail file-count or byte cap. A catalog backup for that refresh is taken after the refresh finishes and still follows the backup gap. A shorter backup gap applies on the next catalog save. Opening the catalog does not read it whole. The source list and source enable and disable read catalog rows, so an imported source is listed and can be toggled without a restart. The tag table is the catalog's tag list. An item can still hold a tag name that is not in that table.
  - `POST /api/play/{itemId}` (persisted library **id** only): returns the same `RandomResponse` shape as random playback, records playback server-side, and emits `playbackRecorded` on SSE; deterministic `404` / `409` / `415` errors with optional `code` on `ErrorResponse`. The play read is that item and its source. Direct play does not block blacklisted items; callers must not double-call `record-playback` for the same start.
  - Unified refresh pipeline: stage/status projection, thumbnail generation, library **duration** / **loudness** via **ffmpeg**/**ffprobe**, and server-scheduled **auto-refresh**. Server shutdown cancels a manual or automatic refresh in progress and does not record that cancellation as a pipeline failure or a completed refresh. Catalog updates that stage has already written stay. A forced duration or loudness rescan stays pending when shutdown cancels that stage. Saving refresh settings schedules the next automatic refresh from the new interval, and clearing a forced rescan keeps the other refresh settings. Clients send refresh **settings** (for example enable/interval) and consume library state via API/SSE only (no authoritative client-side refresh stages or local ffprobe for catalog duration).
  - Replay-aware SSE envelope with reconnect recovery (`Last-Event-ID`, `resyncRequired`, authoritative requery). Both clients resume their event stream with the last event ID, and take the revision of a `resyncRequired` they receive. A stream opened without a last event ID starts with a `streamOpened` event carrying the server's current revision, so a client that receives no other event still resumes from it, including from 0. A last event ID ahead of the server's revision, as after a server restart, gets `resyncRequired`. Duration and loudness refresh progress is published at most every 500 ms, like fingerprint and thumbnail progress, plus each stage's completion.

- **Desktop client (`src/clients/desktop/ReelRoulette.DesktopApp/`)**
  - Thin-client for migrated flows: API command/query + SSE projection (no dual-writer core-state mutation). Shows library projection from the server (including durations) and syncs refresh-related **settings** to the core; **LibVLC**-backed local playback via `LibVLCSharp.Avalonia` `VideoView` / `MediaPlayer` (`--intf dummy`, re-attach when the native host is ready under Avalonia 12) and `NativeBinaryHelper` / bundled `runtimes/.../native/libvlc` on Windows when present.
  - Local-first playback with deterministic API fallback (`ForceApiPlayback` option). Photo or video for the playing item comes from the server's media type; the desktop keeps no extension list.
  - Saved preset durations are read as the server reads them: a number is seconds. Library sort direction labels match the WebUI's, locked by `shared/fixtures/sort-direction-labels.json`.
  - Library panel is grid-only: an infinite-scrolling justified thumbnail grid with sort (name, last played, play count, duration, **date added**), search, filtering, multi-select, and bulk context-menu actions. Browse uses `POST /api/library/query` for the active filter, search, and sort, and appends further results as the user scrolls. The filtered count is the server `totalCount`. Grid activation requests playback through `POST /api/play/{itemId}` (persisted item **id**); LibVLC renders locally from the returned `RandomResponse` without a duplicate client `record-playback` for the same start.
  - Library panel grid uses API-only thumbnail rendering: layout aspect inputs from the list-query page (`hasThumbnail`, `thumbnailWidth`, `thumbnailHeight`); visible tile JPEGs from `GET /api/thumbnail/{itemId}`; justified-row layout via shared `ReelRoulette.Core.Library.LibraryGridLayout` (no local `thumbnails/` reads for grid display). A page applies thumbnail fields and reflows when an aspect changes, including on the unchanged tiles after an inserted or removed id. Resizing the panel reflows the loaded rows after any in-flight grid update and keeps the viewport tile.
  - Favorite, blacklist, playback, and tag updates patch the loaded tiles when they cannot change which files are shown or their order, and reload that window without jumping to the first page when they can. An interrupted grid update does not shrink the window the next reload requests. Holding the scrollbar during that update does not request further pages, and a filter, sort, or reload deferred by that hold is not appended onto the old tiles. A favorite, blacklist, playback, or tag update while a browse query is open, including a further page that has not been applied yet, reads that query again, including before the first page arrives, so the older page cannot replace the update. A tag event that names an item in neither the loaded tiles nor the current file reloads that window when a tag filter is active, after the rest of the event is applied. The grid takes those updates whether the library panel is shown or hidden.
  - A filter or preset change starts over whether the library panel is shown or hidden. The library preset list shows a saved preset or **None** when the filter matches, and a starred row first (`YouTube*` or `None*`) while it does not. Choosing the starred row leaves the filter in place. Choosing **None** restores the default filter and stays on **None** until that filter changes, even when a saved preset has the same filter. Choosing None in the filter dialog leaves the working filter in place and stays on a saved preset when that filter still equals it. The filter dialog heading is `Preset:` plus that same label. Desktop and WebUI compare the loaded presets in memory the same way: tags compare as case-insensitive sets, source inclusion as a set, and per-category match modes in any category order. Desktop remembers that base, and an explicit **None**, across restart. Preset-list sync does not reload the grid.
  - Source sync reloads the grid only when an enabled flag changes. A source enable or disable, and auto-tag apply, refresh the loaded window and keep the scroll position. Now-playing favorite, blacklist, tags, playback stats, duration, and loudness read the loaded tile when that file is on screen. A file that is not on screen is read again on play, refresh, resync, and when the runtime connects. A failed read leaves that copy in place unless the server says the file is gone. A favorite, playback, or tag update for the file being read stays, and an update for another file does not drop that read. The current-file section updates when playback of that file starts, and its last-played line is the time before this play, or Never on a first play. A playback event for a file that is not playing yet does not replace it. A playback, favorite, or tag change for the current file does that read when the file is not loaded. A playback for any other missing file still refreshes global play totals. A tag event applies the rest of its items before that read. Connect and resync wait on library stats, sources, and the tag catalog. Header video and photo counts come from those stats. Stats refreshes after events and actions are coalesced: a short wait gathers a burst, one request is in flight at a time, and requests during it get one more. Filter source names come from the sources API, in that API's display-name order. Tag and category lists come from the tag catalog. Volume normalization in auto mode uses the baseline from the last stats response. Scoped auto-tag scan sends `scanFullLibrary: false` and no path list.
  - Library panel grid supports multi-select (click, Ctrl+click, Shift+click), double-click/Enter to play, right-click bulk context menu (favorites, blacklist, tags, clear stats), and selection count display. **Remove from Library** in that menu, and **Rename** and **Remove** in Manage Sources, are hidden until the server has routes for them.
  - Server version/capability compatibility gating with reconnect/resync guidance.
  - On Linux, when running a Velopack **AppImage** (`APPIMAGE` set), the desktop client reconciles `reelroulette-desktop.desktop` and menu icons under the user’s XDG data home on every launch (same silent reconcile semantics as the server).
  - API-backed source import, duplicate scan/apply, auto-tag scan/apply, and playback-stats clear.
  - Duplicate review dialog renders per-item thumbnail previews via server thumbnail endpoint paths for faster keep/delete validation.
  - Duplicate review dialog supports per-group handling selection with a persisted default behavior (`Keep All` or `Select Best`) from desktop settings.
  - `Library → Export Library…` asks for a destination, then saves a server checkpoint as `library.db`. `Import Library…` requires the server-stopped acknowledgment, then replaces that database and can remap source folders. Import replaces presets and thumbnail revision and dimensions with the imported catalog. Settings and backups stay where they are. JPEG files stay in the local thumbnail directory until the next thumbnail stage completes, which generates thumbnails for the imported catalog and removes JPEG files that are not in it. If import fails before the new database is in place, the previous catalog is put back, and a folder that had no catalog is left without one. A cleanup failure after that leaves the imported catalog in place. The overwrite confirmation names the catalog. An existing `library.db` with sources or items asks for it, and so does one that cannot be opened.
  - Duplicate review comparison metadata now includes per-item tag counts and enriched keep-selection labels (filename + plays/tags/favorite/blacklisted) for faster keep decisions.
  - The tag editor closes on save. The current file, now-playing tag line, and loaded tiles show the new tags immediately. The request runs in the background. A failure puts that save's unconfirmed tags back, leaves tags an event already confirmed, and shows an error when anything was restored. A rename or delete updates the applied filter and cached presets before a tag-filter reload. The other client renames or deletes that tag in its applied filter and saved presets before it reloads, then updates the files that had that tag. Auto Tag apply does the same and still reloads the loaded window once when the save lands. Tag editor and filter `Tags` tab share theme-compatible category/chip surfaces in light/dark mode while preserving filter control behavior boundaries.

- **WebUI client (`src/clients/web/ReelRoulette.WebUI`)**
  - Runtime-config bootstrap, direct API/SSE integration, and startup compatibility/capability checks.
  - Session-aware identity propagation (`clientId`/`sessionId`) through API + SSE paths.
  - Core playback/control/tag workflows aligned with server-authoritative behavior.
  - Refresh status line uses the same stage parsing and consolidated completion summary as the desktop client (including Fingerprint segment); system light/dark follows `prefers-color-scheme` with themed shell and tag-editor surfaces.
  - Player overlay: **Library** (`browse` icon) and edit-tags top-right (left of favorite), mute in the bottom transport row for video (`HTMLVideoElement.muted`, Material `volume_up`/`volume_off`); corner/transport controls use drop-shadow chrome only (media area not dimmed); **Fullscreen** uses a DOM **stage** that includes the media region and the tag/filter/**library** overlays (so dialogs work in fullscreen on desktop); **iOS WebKit** uses in-page pseudo-fullscreen to avoid native video controls replacing the custom UI.
  - Tag editor: category reorder enables Save without other pending mutations; tag chips keep white glyphs/text and shadow treatment in both themes.
  - Tag overlay tabs (**Edit Tags** / **Auto Tag**): filter-style tabstrip with shared header (Refresh, Close) and footer (add category/tag, **Save**). **Auto Tag** sends `scanFullLibrary` with no path list (`false` scans enabled sources on the server), then `POST /api/autotag/scan` and `POST /api/autotag/apply` only (no client-side matching); unified **Save** posts only pending category, tag, and item-tag edits, then auto-tag assignments, closes immediately, and updates loaded tiles before the request returns. A failed save puts that save's unconfirmed tags back, leaves tags an event already confirmed, and does not fetch the tag-editor model again. A rename or delete updates the applied filter and cached presets before a tag-filter reload. The other client renames or deletes that tag in its applied filter and saved presets before it reloads, then updates the files that had that tag. **Close** / **Refresh** prompt to discard when manual and/or autotag changes are pending; scan-full default in `localStorage` (`rr_autoTagScanFullLibrary`).
  - Filter Media overlay (full-screen, same shell pattern as the tag editor): General (basic flags, media type, client source inclusion, audio filter, duration text like desktop), Tags (global AND/OR across categories, per-category local AND/OR, include/exclude tri-state chips from `POST /api/tag-editor/model`), and Presets (catalog edit/save via `POST /api/presets`, header preset list with Material Symbols manage controls). The header preset list shows a saved preset or **None** when the filter matches, and a starred row first while it does not. Choosing the starred row leaves the filter in place. **None** applies the default filter and stays on **None** until that filter changes, even when a saved preset has the same filter. The filter overlay heading is `Preset:` plus that same label. Random playback sends authoritative `filterState` on every `POST /api/random` and includes `presetId` only when the applied filter still equals the selected named preset; presets refetch on dialog open, after successful preset catalog save, and when SSE signals `resyncRequired`; dialog content now uses full-width responsive layout (no large-screen panel max-width cap).
  - Library overlay (full-screen, filter/tag dialog pattern): **Library** corner control opens overlay inside the fullscreen stage; header shows **Showing N of M items** from the query `totalCount` and `searchBaselineCount`; browse uses `POST /api/library/query` (filter, search, sort, fill-on-scroll) with the same window the desktop grid uses. The first page loads after the session can reach the server, before the overlay is opened. Hiding or showing the overlay keeps that window and the scroll position and does not query again. The header counts stay the current query totals after a filter or preset change that finishes while the overlay is hidden. Fill-on-scroll runs only while the overlay is shown. A further page that fails loads again after the scroll position changes. Filter, search, sort, and a header preset, including **None**, start over from the first page whether the overlay is shown or hidden. An empty result still scrolls to the top. Search waits briefly so typing does not query once per character. Favorite, blacklist, playback, and tag updates patch the loaded tiles or reload that window whether the overlay is shown or hidden. Both clients reload only when the change can alter what the loaded window shows or its order, by the same rule (shared fixture `library-tile-effect.json`): a loaded tile reloads when a changed field is in the filter or sort and can take it out or move it, and an item that is not loaded reloads only when the change could bring it in. A tag save made on that client, and a catalog tag rename or delete, still reload under any tag filter. The WebUI has one event stream client. It reconnects after an error and when the page regains focus, visibility, or network, always with the last event ID; an idle stream is not reconnected. `resyncRequired` reloads the loaded window, does not fetch the full catalog, and does not post an empty item-state read. The grid is a virtualized justified thumbnail layout edge-to-edge in the rounded body (Core-aligned `libraryGridLayout` port, row spacers + 900px overscan, desktop tile chrome, themed overlay scrollbar, `GET /api/thumbnail/{itemId}` when `hasThumbnail`); search/sort persist across close/reopen; a new query resets grid scroll to the top; playback continues while open. Single-click tile activation calls `POST /api/play/{itemId}` (persisted item **id**), closes the overlay on success, and starts returned media in the WebUI player without duplicate client `record-playback`; endpoint errors map to status messages (404/409/415); Escape closes overlay; Enter/Space on focused tiles plays; tile focus/active and mobile toolbar wrap signed off in light/dark themes.
  - WebUI includes installable PWA metadata (`manifest.webmanifest`, iOS home-screen meta tags, icons under `public/icons/`) plus a minimal root `sw.js` registered only in secure contexts. The server serves plain HTTP, so on a LAN address the worker does not register and Android Chrome offers only a home-screen shortcut. Installing as an app on Android needs HTTPS, for example through a reverse proxy, after which Chrome can open **Install app** in `standalone` per the manifest. The worker intercepts document navigations only; API calls, the event stream, and media are not intercepted. iOS Safari relies primarily on `apple-mobile-web-app-*` meta. `sync-shared-icon.mjs` (runs before dev/build) uses **`sharp`** to emit **192×192**, **512×512**, and **180×180** PNGs from shared `HI-256.png` / `HI-512.png` so manifest-declared sizes match files.
